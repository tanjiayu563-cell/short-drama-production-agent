# MiniMax H3 视频提示词适配

## 1. 官方核实信息

以下信息依据 MiniMax 官方模型页、视频生成指南与 API 文档，最后核验：2026-11-03。

- 正确名称是 **MiniMax H3**，API 模型名为 `MiniMax-H3`；不要把品牌名写成 “minmax”。
- H3 是开放式通用多模态视频模型，统一接收文本、图片、视频和音频，支持视频生成、参考生成和视频编辑。
- 支持文生视频、首帧/尾帧图生视频、多模态参考生成。
- 输出：768P 或 2K，4–15 秒，仅整数秒，24 fps；官方发布文章称支持原生立体声音频。
- 参考输入上限：图片 ≤ 9 张、视频 ≤ 3 段、音频 ≤ 3 段，混合输入最多 12 个文件。
- 提示词长度上限：7000 个字符。
- 视频生成是异步任务：创建任务、轮询状态、下载结果。
- H3 的 `content[]` 输入中，每个条目由 `type` 和可选 `role` 区分：
  - `text`
  - `image_url` + `first_frame` / `last_frame` / `reference_image`
  - `video_url` + `reference_video`
  - `audio_url` + reference audio（以实际 API schema 为准）
- 官方视频指南示例提到，可在关键描述后加入运镜指令，例如 `[pan]`、`[zoom]`、`[static]`。具体产品入口是否支持这类命令，应在使用时核验。
- H3-Context-IR 是独立的异步任务，只增强提示词，不直接生成视频；成功后从 `content.prompt` 取增强结果。

官方来源：

- <https://www.minimax.io/blog/minimax-h3>，发布日期 2026-07-31；
- <https://platform.minimax.io/docs/guides/video-generation.md>；
- <https://platform.minimax.io/docs/guides/video-prompt.md>；
- <https://platform.minimax.io/docs/guides/models-intro.md>。

## 2. 任务模式

| 模式 | 输入 | 适用情况 |
|---|---|---|
| T2V | 文本 | 没有人物或场景参考图，从零生成 |
| I2V | 文本 + 首帧 | 已有明确的镜头起始画面 |
| First/Last | 文本 + 首帧和/或尾帧 | 需要控制动作起止或转场 |
| Reference | 文本 + 图片/视频/音频 | 需要人物、场景、镜头、动作或声音一致性 |

人物和背景一致性优先使用 `reference_image`，而不是仅在文本里重复形容词。首帧和参考图职责不能混淆。

## 3. MiniMax H3 提示词结构

```text
任务：T2V / I2V / 首尾帧 / 参考生成
模型：MiniMax-H3
输出：{{4–15 的整数秒}}，{{9:16 / 16:9 / 其他}}，{{768P / 2K}}，24 fps

参考素材：
Image 1（reference_image）：{{角色 ID、外观、服装、发型、必须保持的特征}}
Image 2（reference_image）：{{场景 ID、空间结构、光源、色调、必须保持的部分}}
Video 1（reference_video）：{{只参考动作/运镜/剪辑节奏}}
Audio 1（reference audio）：{{只参考声音类型或节奏，不复制未授权音乐}}

目标视频：
{{用自然语言说清：谁，在什么空间，发生什么，情绪如何变化，最后停在哪里}}

时间节拍：
0–{{n}} 秒：{{人物动作 + 摄影机行为 + 环境变化}}
{{n}}–{{m}} 秒：{{下一拍}}
{{m}}–{{总时长}} 秒：{{结束状态}}

视觉：
{{景别、机位、焦段倾向、构图、材质、主色、辅色、饱和度、对比度、光源方向}}

摄影机：
{{固定/推/拉/摇/移/跟；必要时加入 [static]、[pan]、[zoom] 等当前入口支持的运镜指令}}

声音：
{{对白、旁白、环境、拟音、音乐、静默；H3 可生成原生音频，但精确口型仍需核验}}

连续性：
{{人物身份、发型、服装、道具、空间、视线、动作、光线、声音必须保持一致的部分}}

编辑边界：
{{只改变什么；保持什么；不要新增什么}}
```

不要把参考素材只写成“风格参考”。每份素材只能承担一个主要职责，并明确哪些特征要保留、哪些要排除。

## 4. 角色和背景一致性

### 角色卡

```text
角色 ID：
名称/别名：
年龄感：
面部锚点：
发型与发色：
体型与姿态：
服装层级：
关键配件：
色彩归属：
参考图：
必须保持：
禁止漂移：
```

### 场景卡

```text
场景 ID：
名称：
空间结构：
出入口：
主光方向：
实用光源：
主色/辅色：
关键陈设：
背景活动：
参考图：
必须保持：
禁止漂移：
```

生成每个镜头时，把本次使用的角色和场景卡完整带入提示词。不要只写“同一个人”“同一个房间”，因为模型不知道上一镜的隐含状态。

## 5. 多镜头与时间分段

- H3 单次输出 4–15 秒，长叙事应拆成多个镜头后延长或剪辑，不要强行在一个 15 秒片段里塞入完整小说章节。
- 时间分段必须服务于动作和镜头变化，不要为了“看起来详细”写满每一秒。
- 一个生成片段只保留一个主要动作目标；复杂动作拆成多个镜头。
- 需要连续时，把上一镜末帧作为下一镜首帧，或显式写清上一镜结束状态。
- 如果当前产品支持首尾帧，用首尾帧约束运动；如果只支持参考图，则用角色/场景参考图加连续性说明。

## 6. 小说选区到镜头提示词

当用户选中小说文本时，按以下顺序处理：

1. 保留原文作为 `[用户选区]`，不把小说叙述全部当台词；
2. 提取可见动作、对白、环境和情绪变化；
3. 选择镜头功能：建立空间、推进动作、揭示信息、人物反应或留悬念；
4. 为选区确定一个主要动作目标；
5. 从资产库匹配人物、场景、道具；
6. 建立 `Image N` 编号和参考职责；
7. 写起始状态、动作节拍、结束状态；
8. 再加光影、镜头、声音、连续性；
9. 最后生成 MiniMax H3 提示词；
10. 用镜头验收标准检查，而不是只看文字是否流畅。

## 7. H3-Context-IR

如果用户希望得到更完整的提示词，可以：

1. 保留原始提示词和参考素材；
2. 创建 H3-Context-IR 任务；
3. 等待异步结果；
4. 从 `content.prompt` 取增强提示词；
5. 对照原始意图检查是否新增了不该有的剧情、人物或风格；
6. 不把增强结果直接当成最终事实，仍需人工/Agent 复核。

## 8. 不应写进提示词的内容

- 把“同一人物”当成唯一一致性约束；
- 在一个镜头里堆多个人物、多个动作、多个实时文字界面；
- 让模型直接生成复杂可读中文对白或合同文字；
- 用未授权影视片段或真实人物作为参考；
- 用“8K、杰作、极致细节”替代具体镜头和光影描述；
- 把 H3-Context-IR 的增强结果与原始用户意图混为一谈。

## 9. 失败重写

| 失败现象 | 首选修改 |
|---|---|
| 人物身份漂移 | 增加 `reference_image`，减少同镜人数，缩短动作 |
| 服装变化 | 明确服装层级和不可变化锚点，使用同一角色参考图 |
| 背景被重建 | 增加场景 `reference_image`，固定镜头和空间锚点 |
| 动作未完成 | 减少动作数量，拆成起、中、止三个时间节拍 |
| 运镜错误 | 只保留一种主要运镜，写清起幅和落幅 |
| 音频对不上 | 缩短短对白，拆成反应镜或后期配音 |
| 文字错误 | 屏幕文字、品牌字和标题优先后期合成 |

每次只修改一个主要变量，并记录上一版的模型、素材、参数、提示词和评分。
