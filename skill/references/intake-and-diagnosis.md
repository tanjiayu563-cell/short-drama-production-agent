# 接收与剧本诊断

## 1. 建立项目简报

优先从用户内容中提取以下字段。缺失但非关键时使用显式假设，不要静默补全。

| 字段 | 要确认的内容 | 缺失时怎么处理 |
|---|---|---|
| 输入类型 | 创意、梗概、大纲、剧本、已有分镜 | 按实际内容判断并标明 |
| 类型/受众 | 爱情、悬疑、复仇、家庭、喜剧等；年龄与内容尺度 | 从文本推断，标为假设 |
| 发布场景 | 横屏、竖屏、平台、单集或连续集 | 若影响镜头构图则询问 |
| 时长/集数 | 总时长、单集时长、集数 | 沿用用户文本体量；若为一句创意则询问或给条件稿 |
| 制作方式 | 实拍、AI 生成、动画、混合 | 从用户表述推断；仍不明确时在风格闸门确认 |
| 视觉约束 | 必须保留或禁止的风格、色彩、人物、镜头 | 原样记录 |
| 制作约束 | 预算、周期、人数、地点、设备、演员 | 未知时标为待确认，不编造金额 |
| 内容约束 | 敏感议题、品牌、真实人物、版权作品 | 单独列出，进入风险检查 |
| 成功标准 | 用户想让观众感到什么、记住什么 | 提炼 1–3 条，不替用户保证传播效果 |

## 2. 先做输入完整性判断

### 只有创意或一句话

- 提取“人物 + 欲望 + 阻力 + 反转/卖点”。
- 可以提出故事 Spine 和 2–3 个走向，但不要假装已有完整台词和因果链。
- 若用户要求直接做分镜，先建立明确的故事假设与结尾，再进入风格闸门。

### 有梗概或大纲

- 检查事件之间是否由人物选择推动，而不是巧合串联。
- 标出信息差、误会、秘密、代价和倒计时。
- 对缺失的转场补“动作桥”或“信息桥”，并标明为建议。

### 有完整剧本

- 不静默改剧情。逐场记录原文意图和用户不可改内容。
- 将改动分成：
  - `必要修复`：不修会造成逻辑断裂；
  - `建议优化`：提升节奏、视觉性或人物层次；
  - `风格扩写`：不改变剧情，只增加可拍细节。
- 台词冲突、重复信息或场次合并建议必须引用原场次/页码/段落。

### 已有分镜

- 检查镜号、时长、叙事功能、视线、动作接续和技术规格。
- 不重排用户已锁定的镜号；需要增删时使用 `S01-12A` 或单独修订表。

## 3. 剧本诊断框架

逐项判断，不要只给“好/不好”：

1. **前提**：一句话能否说清谁想要什么、被什么阻止、失败会失去什么。
2. **因果**：每一场是否由上一场的结果触发。删掉巧合后故事是否仍成立。
3. **人物动机**：角色是否为目标采取行动；关键选择是否符合其恐惧、欲望和已知信息。
4. **冲突升级**：阻力是否变强、代价是否变高，而非重复同一争执。
5. **信息控制**：观众何时知道、角色何时知道、谁在隐瞒；反转是否有前置线索。
6. **情绪曲线**：期待、紧张、释放、失落或好奇是否形成变化。
7. **节奏**：每场是否有一个不可删的功能；入场是否过晚、离场是否过早或拖尾。
8. **短剧钩子**：开场是否立即建立异常、冲突或强问题；集尾是否产生非看不可的下一步。
9. **视听潜力**：关键信息能否通过动作、空间、物件、声音或表情呈现，而非全靠对白。
10. **可执行性**：场景数、角色数、特效、动作和特殊拍摄是否与已知资源相容。

## 4. 每场最小卡

```text
场次：
原文位置：
时间 / 地点：
在场人物：
人物目标：
阻力 / 对手：
信息差：
关键动作：
情绪转折：
必须保留：
可调整：
预计时长：
制作依赖：
风险：
```

## 5. 诊断输出格式

```text
结论：可直做 / 修复后做 / 需先补故事 / 信息不足
依据：3–5 条具体证据
必须修复：
建议优化：
不要改：
需要用户确认：
```

若提出改戏，至少给出：

- 保留什么；
- 改哪一拍；
- 为什么改；
- 对后续场次的影响；
- 是否有更便宜的替代方案。

## 6. 关键提问原则

一次问齐真正影响交付的字段，优先问选择题。可提供默认值，但不要用默认值掩盖重大假设。

风格方向出现多个可选方案时，必须停下询问。其他问题若可安全假设，先做条件稿并列出待确认项。
