# 视频生成模型提示词适配

## 1. 原则

提示词不是文学描述，而是“一个连续镜头或一次编辑任务”的执行规格。它必须同时描述：

- 主体是什么、保持不变的特征；
- 镜头开始时的状态；
- 动作如何从起点走到终点；
- 摄影机如何运动；
- 光影、色彩和材质；
- 环境与背景活动；
- 声音或静默；
- 任务结束时的可见状态；
- 哪些东西不能被模型自由改动。

模型版本、生成参数和输入模态会显著影响结果。不得把未经核验的能力、参数名或限制写成事实。

## 2. 模型配置文件

当用户指定模型时，先建立或读取 `Model Profile`：

```text
模型名称：
版本：
来源链接：
最后核验：
生成任务：T2V / I2V / R2V / V2V / Extend / Edit
支持输入：文字 / 首帧 / 尾帧 / 多图 / 视频 / 音频 / 白模
是否支持原生音频：
单次生成时长：
是否支持多镜头：
是否支持视频延长：
是否支持时间戳编辑：
参考素材数量与类型：
提示词引用语法：
负面提示词：
随机种子：
画幅 / 分辨率 / 帧率：
已知限制：
未知或待核验：
```

未知字段必须写 `[需核实]`。不要因为某模型支持“多模态参考”就假定它支持精确口型、文字渲染、多人动作或复杂物理。

## 3. 通用提示词结构

```text
任务：{{生成 / 参考生成 / 延长 / 编辑}}
模型与版本：{{已核验}}
画幅、分辨率、目标时长：{{明确参数}}

主体锚点：
{{身份、年龄感、脸、发型、体型、服装、标志性道具}}

起始状态：
{{人物位置、朝向、姿态、道具位置、环境状态}}

连续动作：
{{主体动作阶段 + 摄影机动作阶段，按时间或起承止写清}}

结束状态：
{{人物位置、朝向、手部、道具、表情、环境变化}}

环境与美术：
{{地点、时间、天气、前中后景、背景活动、材质}}

光影与色彩：
{{主光方向、软硬、色温、主色、辅色、饱和度、对比度、肤色}}

镜头：
{{景别、机位高度、角度、焦段、构图、景深、运镜与起幅落幅}}

声音：
{{对白、环境、拟音、音乐、静默；不要求声音时明确写无}}

连续性：
{{必须保持的角色、场景、道具、光线、方向和动作状态}}

禁止项：
{{不得新增的人物、文字、Logo、水印、变形、换装、换景等}}
```

结构可压缩，但不能缺少“主体、动作、镜头、环境、光影、声音、结束状态、连续性”。

## 4. 分镜卡到生成提示词的转换

对每个镜头：

1. 先写 `Shot Intent`：它在故事中完成什么；
2. 写 `Start State` 和 `End State`；
3. 只保留一个主要动作和最多两个清晰转折；
4. 选择一种主要摄影机运动；
5. 把风格形容词转成可观察变量；
6. 指定参考素材职责；
7. 写验收标准；
8. 若模型一次生成能力不足，拆镜。

### 转换示例

分镜：

```text
林夏在门内看小票，焦点从脸转到纸面；她发现订单号与手机一致，呼吸停顿。
```

生成提示词：

```text
竖屏近景，林夏站在门内右侧，面向画面左侧，右手拿黑色手机，左手捏着一张被雨打湿的小票。
起始画面焦点在她的眼睛；她低头看向小票，镜头保持固定，焦点在两秒内从小票移到她的眼睛，再回到小票。
她先皱眉，随后呼吸停住，拇指遮住订单号又移开。
室内旧台灯从右后方提供暖光，手机冷光从下方照亮脸部，走廊绿色荧光从门缝切入画面左侧。
环境声只有雨声、纸张摩擦和一声手机震动；不要配乐。
保持灰色针织衫、低马尾、右手机、左小票、门在画面左侧。
画面中不要新增人物、不要出现平台真实 Logo、不要生成可读字幕。
```

## 5. 素材参考与一致性

把参考素材按职责编号：

```text
@角色图1：只参考林夏的脸、发型、肤色和身体比例。
@服装图1：只参考灰色针织衫的版型、颜色和磨损。
@场景图1：只参考房门、台灯、餐桌与空间布局。
@视频1：只参考镜头运动与节奏，不复制人物和场景。
@音频1：只参考雨声质感，不复制可识别音乐。
```

一致性依靠：

- 同一角色的多角度参考；
- 固定服装和道具；
- 明确屏幕方向与轴线；
- 场景正反打的空间锚点；
- 上一镜末帧与下一镜首帧；
- 固定色彩脚本与光源方向；
- 模型支持时复用同一随机种子；
- 生成后逐镜比对，而不是只检查单镜美观。

## 6. 负向约束

先判断模型是否支持独立负面提示词：

- 支持：把禁止项放入 negative prompt；
- 不支持或不确定：用正向可观察约束描述，例如“画面中只出现林夏和陈默两人”“屏幕保持纯黑”“无字幕、无 Logo、无水印”；
- 不要用负面描述承载核心内容。例如“不要不让林夏拿手机”会造成歧义；
- 不要堆十几个冲突形容词。先修正镜头设计。

## 7. 音频、口型与文字

- 原生音画同步不等于精确台词口型。长对白应拆成短句、反应镜、侧背身或后期配音；
- 画面文字、合同、手机界面和中文标题优先后期合成，尤其是承担关键信息的文字；
- 音乐、人声和可识别声音需要权利核验；
- 环境声可以后期替换，不应为“生成到完美声音”无限重试。

## 8. 其他模型适配

当用户提到 Sora、Veo、Kling、Runway、Hailuo、PixVerse、Vidu、Pika、Wan 或其他模型：

1. 先确认具体产品、版本和入口；
2. 查官方文档/模型卡；
3. 按 `Model Profile` 记录能力；
4. 使用通用提示词结构生成；
5. 仅在该模型确认支持时使用其专属引用语法、时间戳或编辑指令；
6. 未核实的能力写 `[需核实]`，不伪造参数或限制。

## 9. “Muse” 的名称歧义

截至 2026-11-02，公开检索中“Muse”可指向多个不相关产品；可检索到的 Meta Muse 被描述为个人 AI Agent，而不是已核实的视频生成模型。不能仅凭名称假定它是视频模型，也不能编造其提示词语法。

遇到用户说“Muse 视频模型”时：

1. 请求产品链接、厂商、版本或使用界面截图；
2. 确认它是否支持 T2V/I2V/R2V/V2V、音频、参考图、时长和编辑；
3. 按通用 `Model Profile` 建立适配；
4. 未确认前，使用模型无关提示词模板；
5. 不把第三方营销页的夸张描述当作官方能力。

如果用户指的是另一种具体视频模型，也应按相同流程核验，而不是把“Muse”直接写进提示词充当风格标签。
